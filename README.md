# C++ modules

I could not find good examples, so I wrote this.

```
├── cli
│   └── main.cpp
├── lib
│   ├── A
│   │   ├── one.cpp
│   │   └── two.cpp
│   ├── B
│   │   ├── one.cpp
│   │   └── two.cpp
│   ├── C
│   │   ├── one.cpp
│   │   └── two.cpp
│   └── D
│       ├── one.cpp
│       └── two.cpp
└── modules
    ├── example
    │   ├── A
    │   │   ├── a.ixx
    │   │   ├── one.ixx
    │   │   └── two.ixx
    │   ├── B
    │   │   ├── b.ixx
    │   │   ├── one.ixx
    │   │   └── two.ixx
    │   ├── C
    │   │   ├── c.ixx
    │   │   ├── one.ixx
    │   │   └── two.ixx
    │   └── D
    │       ├── d.ixx
    │       ├── one.ixx
    │       └── two.ixx
    └── example.ixx
```

- To use clangd, generate the compilation database with `CMAKE_CXX_COMPILER` set
  to clang. Note that the compilation database generated by CMake contains
  references to `.modmap` files, e.g.
  ```
  /usr/lib64/ccache/clang++ -O3 -DNDEBUG -std=gnu++23 -fcolor-diagnostics -Wno-reserved-module-identifier @CMakeFiles/__cmake_cxx23.dir/usr/include/c++/15/bits/std.compat.cc.o.modmap -o CMakeFiles/__cmake_cxx23.dir/usr/include/c++/15/bits/std.compat.cc.o -c /usr/include/c++/15/bits/std.compat.cc
  ```
  `cmake --build <DIR>` has to be run at least once in order to create these
  files.

- [CLion](https://www.jetbrains.com/clion/) takes care of everything itself
  (without building the project), though its static analysis is often wrong when
  using modules. For example, it does not mark unresolved symbols as errors,
  probably to minimize false errors.

> [!NOTE]
>
> To use `import std`,
> see `https://github.com/Kitware/CMake/blob/v${cmake_version}/Help/dev/experimental.rst`
> and set `CMAKE_EXPERIMENTAL_CXX_IMPORT_STD` accordingly.
